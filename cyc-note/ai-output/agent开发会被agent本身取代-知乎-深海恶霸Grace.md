# 网上很多人鼓吹agent有前途，但agent开发会不会被agent本身取代？

> 来源：深海恶霸Grace 的知乎回答

原文链接：<https://www.zhihu.com/question/2091291972199883979/answer/2092928266030134121>

## 正文

所有的回答和评论我都看了一遍，感觉大家讨论的可能不是同一个问题。

尤其是把： **“Agent 会写代码了”** 直接推导成： **“Agent 开发没有前途了，因为 Agent 自己就能开发 Agent。”** 这个推导本身就有问题。

而且我感觉，“Agent 开发会不会被 Agent 自己取代”这个问题，本身就没有太大的讨论价值。因为今天还有多少工程师是在完全脱离 AI、从第一行代码开始手写一个完整系统？至少我身边极度的稀少，让AI干活，偷懒谁不愿意啊。

包括我自己现在设计 Agent 应用，本身也在大量使用 Codex 这类通用 Agent。难道因为 Agent 帮我写了代码、帮我改了代码，就意味着我设计出来的 Agent 应用没有价值了吗？

**真正应该讨论的不是“代码是不是 Agent 写的”，而是“谁有能力把 Agent 变成一个真正可用的产品和系统”。**

## 一、我觉得大家最大的误区，是把“会用 Agent”与“会开发 Agent”混为一谈

现在很多人看到 Codex、Claude Code 之类的能力之后，会产生一个非常自然的判断：

以前开发软件需要程序员，现在我把需求告诉 Agent，它自己就能写出来，那程序员还有什么意义？

这个问题其实几年前就已经出现过一次。

低代码出来的时候，很多人说：

“拖拖组件就能开发软件了，程序员是不是要消失？”

后来 Copilot 出来的时候，又有人说：

“AI 已经能写代码了，程序员是不是要消失？”

现在这个问题升级成：

“Agent 已经能自己完成开发了，那 Agent 开发是不是也要消失？”

但这里一直存在一个非常核心的误区：

**把“生产工具变强”理解成了“生产能力消失”。**

实际上恰恰相反。

Photoshop 让设计师不需要自己画每一个像素，不代表设计师消失了。

相机让摄影师不需要自己制作底片，不代表摄影师消失了。

编译器让程序员不需要自己写机器码，不代表程序员消失了。

现在 Codex 让程序员不需要自己手写大量代码，同样不意味着软件开发这件事情消失了。

它改变的是： **一个人的生产半径变大了。**

## 二、我自己最大的体感是：Agent 开发并没有比以前的开发简单，反而增加了新的复杂度

以前开发一个普通应用，大概是：

产品需求 → 前端 → 后端 → 数据库 → API → 测试 → 部署

现在一个真正可以落地的 Agent 应用，除了这些东西之外，还多了一层：

Model → Context → Tool → Memory → Permission → Agent Loop → Workflow → Evaluation → Observability → Human Intervention

而且这里面很多问题，传统前后端开发根本没有消失。

例如一个 Agent 要查询客户信息，你仍然需要：

- 前端界面
- 后端接口
- 数据库
- 用户认证
- 权限系统
- API
- 日志
- 错误处理

然后 Agent 这一层再增加：

- 它什么时候可以查询？
- 它能查询哪些客户？
- Tool 怎么设计？
- 参数怎么定义？
- Tool 返回什么？
- 查询失败怎么办？
- Agent 判断错了怎么办？
- 它有没有权限执行下一步？
- 哪些操作需要人工确认？
- 怎么记录 Agent 做过什么？
- 怎么判断这次任务到底完成没有？

所以Agent 不是把传统软件开发抹掉，而是在传统软件工程之上增加了一层新的复杂度。

## 三、而且有一个特别现实的问题：不是每个人都能把通用agent用好

这个其实是我对“Agent 会取代 Agent 开发”这个观点最不认同的地方。

现在 Codex、Claude Code 这类工具， **几乎每个人都可以使用** 。

但问题是：

**每个人都可以使用 Codex，并不意味着每个人都可以用 Codex 做出一个真正可用的 Agent。**

这和编程其实是一模一样的。

现在任何一个普通人都可以对 Agent 说：

“帮我做一个电商网站。”

Agent 可以给他生成：

- React
- Next.js
- Node
- 数据库
- 登录
- 支付
- 管理后台

甚至看起来还能运行。

但真正把这个东西放到生产环境，马上就会出现大量问题：

数据库设计合理吗？权限有没有漏洞？支付流程有没有问题？为什么这里需要事务？出问题以后怎么排查？

最关键的是：

**如果你自己没有这些基础知识，你甚至不知道 Agent 给你的方案到底对不对。**

这就是为什么现在“Vibe Coding”可以让大量非传统开发人员做出 Demo，但真正能够稳定进入生产环境的东西，远没有 Demo 那么多。我知道肯定很多人会否认，我刷小红书看到很多人分享的Vibe Coding的案例，看起来都有模有样但是他自己说不出个一二三的。

## 四、Agent 应用对专业能力的要求可能更高

以前一个普通程序：你写什么，它就执行什么。

而 Agent 是：你给它目标，它自己决定下一步做什么。

这意味着你不但要写“程序”，还要设计： **这个 Agent 在什么边界里面自主行动。**

比如一个企业 Agent。

你不能简单地告诉它：“帮我处理客户售后。”然后给它几个 Tool 就结束了。你必须继续考虑：

```
查询订单
    ↓
判断售后政策
    ↓
决定是否符合退款条件
    ↓
计算退款金额
    ↓
执行退款
```

那么问题来了：

**谁允许它决定退款？**

如果金额超过 1000 元怎么办？

如果客户信息和订单信息冲突怎么办？

如果 Agent 理解错政策怎么办？

如果 Tool 返回异常怎么办？

如果退款已经成功，但是 Agent 没有收到结果怎么办？

如果它重复调用退款 Tool 怎么办？

**你看如何让一个不完全可控的智能体，在一个真实业务环境里面可靠地完成工作才是难点。**

## 五、Agent 开发真正的门槛正在从“写代码”转向“判断”

首先未来代码生成一定会越来越便宜这个大家不否认吧。

甚至：一个普通开发者 + Codex 可能就能达到过去一个小型开发团队的代码产出量。

但这并不意味着：一个完全没有软件工程经验的人 + Codex。就等于：一个有多年工程经验的人 + Codex。

因为真正拉开差距的东西正在从： **“我能不能写出来？”** 变成： **“我知不知道应该怎么做？”** 再进一步： **“我知不知道 Agent 给出的十个方案里面哪个是对的？”**

## 六、为什么我觉得“Agent 会不会取代 Agent 开发”这个问题没有意义

因为按照这个逻辑，今天应该已经没有程序员了。

毕竟：

- Copilot 可以写代码
- Cursor 可以写代码
- Claude Code 可以写代码
- Codex 可以写代码
- 各种 Agent 可以自己 Debug
- Agent 可以自己写测试
- Agent 可以自己重构

但是现实是什么？

程序员没有消失，只是工作方式发生了巨大的变化。当然了，大量程序员失业了也是社会现实，但是这是多方面的原因，一方面供大于求，另一方面低价值的业务AI做起来又快又好，一个有经验的开发可以做好几个项目（牛马的悲哀）！

所以以后一定会出现：Agent 写 Agent 的代码。Agent 设计 Agent 的部分架构。我觉得这都完全正常。

但最后仍然需要有人判断：

> **这个 Agent 到底应该解决什么问题？**  
> **它应该拥有什么能力？**  
> **哪些事情应该让它自主完成？**  
> **哪些事情不能让它碰？**  
> **它的结果怎么验证？**  
> **怎么进入真实业务？**  
> **出了问题谁负责？**

## 七、Agent 越强，Agent 工程反而越重要

这个逻辑乍看有点反直觉。

但你想一下：如果 Agent 只能帮你写一段代码，那么你可以盯着它。

如果 Agent 可以：自己写代码 → 自己部署 → 自己调用数据库 → 自己操作企业系统 → 自己完成业务流程

那么你反而更加不能放任它。

否则后果你懂的，不是只有人才能“删库跑路”。

## 八、现实中有没有那么多要用到 Agent 场景的需求

不是所有软件都需要 Agent 这个观点我是同意的，但是未来有没有那么多 agent 场景还能难说。以前软件行业是经历过类似的过程的，现实中到底有多少事情需要网站？手机上到底有什么事情非得用 App？

是吧，你说目前没有形成大量成熟的 agent 应用我承认的，但是未来有没有，不好说。

而且还有个问题就是，agent的价值不是替代一个岗位，这其实把门槛设得太高了。我们先想想能不能把一个人的工作从8小时减到5小时，这就已经很有价值了，甚至是在创造新的软件需求。

**不要低估了长尾需求！**

这也是个很容易被大家遗忘的点，我举个极端点的例子，一个大型企业可能有200 个业务流程，其中100个适合传统软件，30个适合workflow，20个适合agent，剩下50个过去可能因为成本太高，一直靠人处理。那么有可能 agent 的机会不是来自于那100个已经被软件化的流程，而是来自于那一堆过去“没人觉得值得开发软件”的人工工作。这部分工作从来没有进度到工程师的视角内，但是他存在！

### 所以Agent 有前途吗？

**我认为有，而且现在讨论“Agent 是不是已经没机会了”其实还太早。**

### Agent 开发会不会被 Agent 本身取代？

**代码生产一定会越来越多地被 Agent 完成，但这不等于 Agent 开发本身没有价值。**
