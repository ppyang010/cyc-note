# 其他部门同事不配合工作怎么推都推不动怎么办?

> [!info] 来源信息
> - **作者**：会飞的女巫
> - **来源**：[知乎回答](https://www.zhihu.com/question/2076224621884527812/answer/2090409392835506606)
> - **赞同 / 评论**：481 / 11
> - **编辑时间**：2026-10-10 08:17
> - **抓取日期**：2026-10-10
> - **说明**：前半是阅读整理，末尾保留清理后的原文。书中方法、案例和效果判断均属于原作者叙述，本次未独立核验《Getting It Done》原书。

> [!warning] 使用边界
> 这是在没有任免权和奖金权时推动平级的协作方法，不是授权去施压、设局或公开针对具体人。涉及绩效、资源分配和向上汇报时，事实、口径和权限仍要按本部门规则核对。

## 一句话总结

==没有任免权和奖金权时，催不动是常态。与其命令或建议同事，不如找到对方在这件事里的利益，把阶段性结果带回上级，再用公开的项目焦点而不是针对人来维持协作。==

原文把问题收成一本查理·芒格推荐过的书：《Getting It Done》。作者认为，平级推动的关键不是更用力地催，而是承认自己只是带头干活的人。

## 一、先丢掉「安排了就该听」

| 现实 | 含义 |
| --- | --- |
| 不能开人，也不能取消奖金 | 责任大，但没有对应权力 |
| 同事比你更清楚这一点 | 「当然不听」是结构问题，不是偶发态度问题 |
| 硬催、翻白眼、搬上司压人 | 都不能补上缺失的权力 |

## 二、找到对方的拉环，而不是砸罐子

原文把同事比作易拉罐：硬砸没用，要找到那个拉环——对方关心什么、想要什么。

书里用马克·吐温笔下汤姆让朋友刷墙的例子说明：让对方相信，他在意的东西就在眼前这摊项目里，人才会自己动起来。作者说书里把这叫「明确工作目标」，直译就是找到共同利益。

可操作的问法：

- 这件事做成，对方能拿到什么：曝光、资源、减少返工、避免背锅、专业上被看见。
- 这件事拖着，对方会损失什么：已有的阶段性认可、和其他同事共享的成果。
- 这个利益是否真的在当前项目里，而不是你口头许诺一个你分配不了的好处。

## 三、向上表功是为了把饼带回来

阶段性成果出来后，原文建议及时找上级表功，请领导把注意力和资源继续投到团队上。潜台词有两层：

1. 同事关心的利益，你要能帮他们分到；你自己也在领导那里留下「有功劳」的印象。
2. 这些反馈是不可替代的前期积累。别人不配合时，会先掂量代价：不配合等于去咬其他同事已经拿到的成果。原文把这叫损失厌恶，认为其他同事会自己把不配合的人按住。

> [!warning] 不要误读成邀功甩锅
> 表功的对象是团队阶段性成果和继续投入的理由，不是把同事的工作说成自己的。没有可核对的成果，就没有可分配的「饼」。

## 四、千万不能做

| 不要 | 改为 |
| --- | --- |
| 建议或命令同事 | 开放讨论。原文强调：建议也会被解读为指责 |
| 公开场合针对具体人 | 把焦点放在项目的具体支点，而不是负责人 |
| 只顾埋头做事，忽略场景和人 | 注意同事之间的矛盾，公开或不公开地讨论，邀请共同行动，并率先给出解决办法 |

后两条的共同提醒是：不要糊里糊涂得罪人。原文还补了一条能力前提——自己的岗位先做顺，并能帮同事解决专业困难。理想结局不是人人听你的，而是互相支持的氛围被维持住。

## 五、下次推动前可核对

- [ ] 我是否还在用自己没有的权力下命令？
- [ ] 对方在这件事里真正关心的利益是否已经说清，而且我带得回来？
- [ ] 阶段性结果是否已向上同步，资源是否还在往团队上投？
- [ ] 讨论焦点是项目支点，还是某个人？
- [ ] 我有没有先拿出一个可执行的解法，而不是只催进度？

查理芒格推荐过一个教程，Getting It Done，专门教你怎么领导你的平级，让同事干活。

**你没有领导的身份，也没法搬上司来压人。**

催这个，这个不动。

催那个，那个翻白眼。

丢掉幻想，这个场景，你在职场生存绕不开。

## 怎么做？

### ① 丢掉幻想

**不听你的才是常态**

**如果你不能开了他们，也不能取消他们奖金。**

**那你其实只是组织团队带头干活，你责任很大、但没有权力。**

这一点，同事比你更清楚，所以你安排工作，同事当然不听。

### ② 找到同事和你的共同利益

同事这个东西，好比易拉罐。

他关心什么、想要什么，什么就是你牵动他的那个拉环。

对待易拉罐，硬砸没有用，你把他的拉环找出来就好了。

getting it done用了马克吐温写小汤姆让朋友刷墙的例子。

你也这样办，找到同事关心的点，让他相信，那就在你们眼前这一大摊子项目里。

那么同事就会自动自发地起来干活。

作者用词很委婉，说这个叫“明确工作目标”，其实就是找到同事和你的共同利益。

![](https://picx.zhimg.com/v2-72783560e70cf3a1bd9e8d9e06e7b194_r.jpg?source=2c26e567)

### ③及时向上表功

万幸，团队项目终于出了阶段性成果

你一定要找到上级，及时表功

催促领导多多把注意力和资源投入到你们的团队。

雏鸟想吃大鸟喂的虫子，也会争相张大嘴向大鸟呐喊。

你也得学会向上喊。

喊完了，把饼带回来。

### ④向上表功的潜台词

及时向上表功，用意是什么

一个，在②中同事关心的利益，你能帮他们分配到。你个人也在领导那里留下了有功劳的印象。

这属于双赢的好事

再一个，这些表功的反馈，是你在领导那边的前期积累，不可替代。

有人再不配合你，他自己会先来个称斤论两。

而且其他同事通过你得到了阶段性表功，他不配合你，等于去咬其他同事嘴里的蛋糕，简直不用你说话，其他同事会按下他。这叫损失厌恶。

## 千万不能做

**①不能建议、命令同事**，要开放性讨论。是的，建议也不行。Getting It Done反复强调多次，建议会被同事解读为指责。

**②公开场合不能针对人**。这个说的是公开场合，你和同事们工作、讨论的时候，你要把讨论焦点放在项目的具体支点，不是具体负责人。

以上两点，其实说的都是提醒你不要糊里糊涂得罪人。

**③不能只顾埋头做事，忽略场景和具体的人。**这一点的相关篇幅，占比相当高，看来相当多的人曾经在这一点上翻过车。

作者给出了好几种解决方法，包括但不限于注意其他同事之间的矛盾、经常召集同事进行讨论（公开和不公开的讨论）、邀请同事共同行动、率先给出解决办法等等。

![](https://pic1.zhimg.com/v2-3ff219031f4b26cefa971d9932aff80e_r.jpg?source=2c26e567)

再一个，你要有优秀的专业水平。

最好自己岗位得心应手，还能帮同事解决他们的专业困难。这一条先不用展开。

此处的最佳结局，是你营造出互相支持的团队氛围并且精心保持。

做成这个，你也不用担心领导平级，大家不配合你了。

Getting It Done 是本好书，难怪得到了查理芒格推荐。

读完你会发现，简洁清晰，永远落在重点上，非常有实操价值。

**唯一的缺点是作者用词太委婉。**

我必须这么翻译一下他的潜台词，翻译成直白坦诚型，不要见怪。
