# 如何系统性的学习RAG、Agent、MCP?

我建议围绕同一个小项目学，这样每增加一个概念，都能看到它解决了哪项具体困难。比如做一个只读的文档助手，资料先用自己有权使用的几篇公开文档。

开始时让程序读取指定文档，把相关段落交给模型，回答时附上出处。刻意放进一个文档没有答案的问题，检查它会不会编。这个版本很简陋，但已经能帮助你区分模型生成能力和外部资料提供的证据。

当文档变多，再补检索。保存标题、版本和段落位置，先取回候选片段，再组织模型输入。全文检索也能作为起点，向量库并非每个练习的必选项。准备一组固定问题，人工标出需要哪些证据，检查遗漏发生在检索阶段还是最终输入阶段。

接着把“搜索文档”和“读取指定章节”做成两个工具。应用向模型提供工具名称、用途和参数结构，模型返回调用请求，由程序校验后执行，再把真实结果交回模型。这里要亲手看一次调用记录，理解模型产生请求和工具实际执行之间的区别。

只有当模型需要根据当前结果继续决定动作时，再写执行循环。例如找到旧版说明以后，判断需要继续查新版。给循环设置步数和时间上限，故意让工具失败，检查系统能否停止并说明缺失信息。Anthropic 的 Agent 架构文章解释了固定工作流与这种动态循环的差别。

最后学习 MCP。把其中一个只读工具接成 MCP 服务，再观察应用如何发现工具和完成调用。此时你能辨认协议接入新增了什么，也能看到参数检查、用户权限和失败处理仍然属于应用与业务服务的责任。

这几部分可以组合，但并非三个必需叠满的层。固定文档问答可能只需要 RAG，确定的处理流程可以保持 Workflow，Agent 也可以调用普通函数完成任务。

每完成一段，就留下一份问题集和调用日志。它们能让你解释检索为什么漏条件、工具为什么被选错，以及一次修改究竟改善了什么。拿着这些问题再看框架教程，会更容易理解框架替你管理了哪些工作。
