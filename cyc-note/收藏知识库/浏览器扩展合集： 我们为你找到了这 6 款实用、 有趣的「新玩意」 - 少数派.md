ZebuClip：提高复制粘贴效率
-----------------

[@kokdemo](https://sspai.com/u/kokdemo)：根据[这份报告](https://sspai.com/link?target=https%3A%2F%2Farmedia.com%2Fblog%2Ffederated-search-the-importance-of-being-able-to-find-information%2F)，一个企业雇员每天花费约 2.5 小时来搜索寻找信息。大部分和我一样的工作者，每天的工作内容基本就是信息的聚合、处理、输出，在前两个环节中，复制和粘贴是最高频的操作之一。

有没有什么办法可以提高复制粘贴的工作效率呢？接下来请让我为你介绍我开发的浏览器扩展 ZebuClip。

对于上述问题，大部分剪贴板应用的解决思路是存储复制历史，然后通过列表、卡片的形式让用户重新再找出来使用。我工作的场景中也会批量复制大量的内容，但这些内容超过三天之后基本就没有使用价值了，使用这类工具很容易让整理成本越来越高。

我需要的是能快速找到和复制内容，然后快速把它们完整转移到一个新文档里去进行加工，基于这种「打开复制模式——网页中快速摘录复制——批量整理——一次性复制和导出」操作模式，我从三个方面优化了 ZebuClip 的操作流程：

*   快速复制：避免用户一遍又一遍的按键和对应的错误
*   复制提醒：提示哪些复制过了，哪些还需要复制
*   支持更多格式的复制

其中前两个场景，我通过划线复制和高亮提醒来进行优化，ZebuClip 的样式支持高亮和下划线两种效果；如果你担心自己会误操作，也可以打开划线后确认模式。

你估计已经看到这个动图里面还支持了段落复制、链接复制和图片复制等功能。除此之外，它还支持复制列表、表格与引言等内容。不过到这里可能会有朋友要问了：

> 等等！这怎么看起来像是个剪藏工具？

是的，如果一直给剪贴板列表塞进超级多的内容，后续内容维护将是一场灾难。出于这个考量，我给这里加了一个重要的「上限」功能。你必须在上限满了之后，处理当前剪贴板里的内容——可以选择导出、粘贴或清空它们，通过这种人为的限制，降低每一次处理剪贴板内容的心理成本，让这个功能不会成为你的新负担。

![](https://cdnfile.sspai.com/2026/05/26/711da536b10a438eeb51ab44c4a4f30a.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

同时，当前的剪贴板应用都提供了粘贴功能，大多是将列表内容再次放进剪贴板中，供你再次粘贴。若此时你的列表中有 20 条内容，难道还得再按 20 次 Ctrl + V ？为了让你更高效快捷的粘贴，ZebuClip 允许你将复制的富文本信息（如前面的段落、链接、图片等）粘贴为纯文本、Markdown（用于各种编辑器）或富文本（用于Word、各种在线文档）状态；如果你觉得单条复制太麻烦，也可以点击批量复制按钮，这会将列表中所有内容塞进剪贴板。

![](https://cdnfile.sspai.com/2026/05/26/f2a6d5cef6c81e6fffb6f20b255adc31.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
![](https://cdnfile.sspai.com/2026/05/26/18cb9c55df3f529ff13e78233cc995d2.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
![](https://cdnfile.sspai.com/2026/05/26/e77808e5acfe224f2dc3a79a4afa427b.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

要是你觉得批量粘贴都不够，你还可以将它们下载到本地，目前支持了 TXT、CSV、Excel、JSON、Markdown 五种格式的文件下载，你可以导出后到其他软件里继续操作。即便你的使用场景不是粘贴到文档里，ZebuClip 也提供了 API 分享的功能，你可以直接单条内容或批量内容通过 API 和 URL Scheme 传递到其他软件和应用。目前已经支持了 Flomo、Notion、Obsidian、Logseq、自定义 API 五种模式，后续可以按大家需要新增更多的场景。

OpenCookie：开源、免费的 Cookie 编辑器
----------------------------

[@幽梦](https://sspai.com/u/52wb3t93)：我平时做开发、调试时要频繁地改浏览器缓存（cookies）：验证登录态、复现某个只在特定 cookie 下才出现的 bug、把一套登录信息从一个环境搬到另一个环境……浏览器自带的开发者工具能看能改，但操作起来零碎，复制粘贴一长串值很容易出错。于是一开始我和很多人一样，去装了个 cookie 编辑器扩展。

但装的时候我才意识到一件事：cookie 里装着登录态、会话凭证，某种意义上就是你在一个个网站上的「钥匙」。如果要把这一级别的访问权交出去，我个人会希望这个工具最好能看到源码、能确认它没把我的数据偷偷传到哪儿去。所以干脆自己写了一个，它叫 OpenCookie。

![](https://cdnfile.sspai.com/2026/06/09/4b65315d81690e9f981c27420d1f69c7.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

OpenCookie 围着这三条核心原则设计：

**零数据上传。**  没有服务器、没有统计、没有任何追踪。你的所有 cookie 操作，自始至终只发生在你自己的浏览器里，一个字节都不会离开。它根本就没有「往外发」这条代码路径。

**权限最小，而且按需授权。** OpenCookie 装上的时候不会向你索要任何网站的访问权限，并且只有当你真的要在某个站点上操作 cookie、点了授权按钮，它才能拿到那个站点的 cookie 权限。你也可以选择「只授权当前站点」或「授权所有站点」，完全由你决定给到哪一级。

![](https://cdnfile.sspai.com/2026/06/09/0bb0e77a8eea08d6c3336353129a782a.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

**代码小到你能自己读完。**  OpenCookie 是纯 JavaScript 写的，没有构建步骤、没有框架、没有打包后看不懂的产物，仓库里的代码就是跑在你浏览器里的代码。整个项目小到你花点时间能自己从头读一遍。

功能上，OpenCookie 就是一个称手的 cookie 编辑器，常规那套：

**查看**：打开就列出当前标签页的所有 cookie，名称、值、域、路径、过期时间、Secure / HttpOnly / SameSite 这些属性都看得到

**增、删、改**：单条增加、编辑、删除；也支持「清空当前页全部 cookie」（会先让你确认，避免手滑）。cookie 的值可以一键复制，不用手动框选那一长串

**搜索过滤**：cookie 一多就用顶部的搜索框按名称或值实时过滤，快速定位

**JSON 导入导出**：可以把 cookie 导出成 JSON（复制、或存成文件），也能粘贴 / 选文件导入。格式和常见的 cookie 工具兼容，方便在不同环境之间搬运，或者备份一份

![](https://cdnfile.sspai.com/2026/06/09/5a436beba8c629d52940720870ca4412.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
![](https://cdnfile.sspai.com/2026/06/09/0d652c0b0fae93d708f919e804bb8bf7.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

**明暗主题**：支持浅色、深色模式，切换后会记住你的选择

![](https://cdnfile.sspai.com/2026/06/09/71660b915660a59e9136acc9106d6cc8.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

**OpenCookie 坚持纯 JS、不上构建，所以**仓库里的代码和实际运行的代码之间没有任何打包工具，这意味着「所见即所跑」——你克隆仓库下来读到的，就是装进浏览器跑的，没有中间商。同时，因为采用了 **JSON 通用格式，如果有需要你也可以**随时能把数据导出去给别的工具用，也能从别处导进来。

现在上了 Chrome Web Store。如果你更习惯自己跑源码，仓库里也写了从源码加载的步骤，毕竟它本来就是完全开源、可审计的。

你可以在 [Chrome 商店](https://sspai.com/link?target=https%3A%2F%2Fchromewebstore.google.com%2Fdetail%2Foiidchgmgceclcobnphmglglbccmmeog%3Fsource%3Dclyde%26source_platform%3Dsspai)下载安装 OpenCookie，欢迎试用，也欢迎反馈，希望它能帮上你。

Lumno：让浏览器的一切搜索即达
-----------------

[@枯白啃设计](https://sspai.com/u/kubai)：

![](https://cdnfile.sspai.com/2026/07/01/99543d37d6986706e78db8a188870a56.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

Lumno 的 slogan 是 「Your browser, at command」，借了 command 的双关

年初，我将主力浏览器从 Arc 切换回了 Chrome。都说「生命在于折腾」，我给 Chrome 开启了垂直标签页，又打开了 Gemini 侧边栏，让它尽可能贴近自己的使用习惯，但总觉得还差点意思。

思来想去，我发现自己最忘不了的其实是 Arc 的搜索框：它抽离了传统浏览器地址栏的部分功能，又几乎取代了新标签页，非常适合我这种喜欢键鼠同步操作的人。

![](https://cdnfile.sspai.com/2026/07/01/474a169a16b1304f2af8369bdbd7b016.jpg?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

Arc 浏览器的标志性设计之一：搜索框

为了复刻这一体验，我启动了 Lumno，也希望借此探索更多浏览器交互的可能性。

Lumno（/ˈluːm.noʊ/）是一款浏览器端的「聚焦搜索」插件。它可以搜索书签、历史记录、常用网站，也可以执行站内搜索、AI 网页搜索、浏览器页面搜索等操作。它开源、免费，不收集任何用户浏览器数据，也兼容 Dia、Comet、Atlas、Helium 等各类 Chromium 内核的 AI 浏览器。

对于熟悉 macOS 聚焦搜索（Spotlight）、Arc 浏览器、Raycast 或 HapiGo 等产品的朋友来说，Lumno 的交互形式应该并不陌生：通过快捷键唤起，键入关键词，再按回车执行。目前，插件支持以下几类搜索结果，可用中文、英文、日语搜索，并支持汉语拼音。

搜索书签（Bookmarks）、历史记录（History）和常用网站（Top Sites），帮你减少「收藏即吃灰」的情况。

![](https://cdnfile.sspai.com/2026/07/01/071b28f98f49f6a5f48c3ca352b06db9.gif)

在网页上唤起 Lumno「搜索栏」

搜索浏览器页面（Browser Page），如下载页、书签管理器、扩展页、flags 页、商店页等。不必再苦苦寻找按钮，也不用输入一长串 URL。

![](https://cdnfile.sspai.com/2026/07/01/2c14790de6a5b556cac11c1e60e3452c.jpg?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

可快速跳转至浏览器页，支持中英文

搜索特定站点内容，这是浏览器地址栏里的经典功能，在 Lumno 中也能用。输入触发词后，按下 Tab 即可进入站内搜索模式。插件内置了近 20 个网站的站点搜索配置；如果你想自定义，也可以在「设置」中添加包含 query 参数的 URL。

![](https://cdnfile.sspai.com/2026/07/01/643f0e85938bf4fcd0c9d0aa2b275a97.gif)

直接展示特定站点的搜索结果

Lumno 还可以帮你把 prompt 直达 AI 网页，减少中间操作。例如输入「豆包」后，按下 Tab，再输入 prompt 并回车，浏览器会直接打开豆包网页版并开始对话。

![](https://cdnfile.sspai.com/2026/07/01/03c6f8c25493b07780b019406e2add86.gif)

目前支持 Gemini、GPT 等数十种常用 AI 网页

除了上述内容，搜索结果中也会包含搜索引擎联想词。总而言之，Lumno 会通过一套内置的相关性评分与排序逻辑呈现以上结果。你可以自定义结果优先级，也可以控制某类或某条内容是否显示。

![](https://cdnfile.sspai.com/2026/07/01/203f8d1c27b4f416e7e4d574f515106a.jpg?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

「置顶标签页存储」：关闭浏览器窗口，或退出/重启浏览器后，可以恢复此前的置顶标签页

E2N：好内容一键进笔记
------------

[@LanceLee2026](https://sspai.com/u/lancelee)：

这大半年我一直被一个问题所困扰：为了查资料看教程，我每天要在各个平台反复横跳，看到有用的东西就想存进 Obsidian 或 Notion 留底。但这事实在太折磨人了：现在很多平台的排版在跨软件复制时经常错乱，比如遇到带公式的长文，手动摘录排版极其痛苦；B 站和 YouTube 的长教程更头疼，看到重点想记下来，只能反复暂停、切窗口、码字……

市面上有很多主打「稍后阅读」的云端书签，但我不太需要那些。我只想简单粗暴地看到啥，点一下，直接变成干净的素材，落到我指定的位置里。毕竟还是要喂给 AI 一起阅读协同工作的——总之找了一大圈儿没遇到顺手的，所以我就干脆自己花了 3 个月时间，连做带测搞了一个浏览器插件，叫 E2N (Everything to Notebook)。

**E2N 主要做三件事。** 

首先是精准提取网页正文。随便一个网页右键选「剪藏此页」，它会把侧边栏、广告这些乱七八糟的东西过滤掉，尽量保留正文和图片。国内平台我也特意针对排版做了优化。比如知乎，它能带上来源 URL，公式也会尽量转成 LaTeX；至于小红书那种图文，你可以填个大模型 API 让它做 OCR，连图带字一起抽出来。

![](https://cdnfile.sspai.com/2026/07/10/500b72a735bdeac0b0776c19d8d0b714.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)
![](https://cdnfile.sspai.com/2026/07/10/452750744e088bc89656824d259a7fd9.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

然后是处理视频，这也是我自己最最需要的功能。如果 B 站或 YouTube 视频教程本身带了纯文本字幕，它会直接把字幕提取出来，一两秒的事，不费什么大模型 Token；要是遇到没有字幕的播客或视频，它能直接通过大模型 API 进行语音转写。这部分都是走自己的 Key 直连厂商，插件本身不经手数据。

![](https://cdnfile.sspai.com/2026/07/11/9078916ccb5b84f7304ec3fae1c1d617.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

收集字幕→AI 消化整理→沉淀知识库

最后一步是多端推送。我平时查资料喜欢同时推两个地方：一份进 Obsidian 做长线积累，另一份扔进 NotebookLM 方便马上提问。所以拿到干净内容后，如果是 Obsidian，E2N 会通过 Local REST API 直接写进本地 vault，完全不过外网；飞书、Notion 和 NotebookLM 也都做了接入。目的地只要支持，原网页的图片和内嵌视频都会一起带过去。

![](https://cdnfile.sspai.com/2026/07/11/b9bcbca30e8a0d828aebd8d3d5be8a00.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

因为它定位就是一个轻量的前端「小铲子」，所以没有账号系统，也不上传任何你的浏览记录到什么云端。所有的动作全在本地和你的知识库之间发生。

E2N 没有独立的 APP 或桌面客户端，它就是一个纯正的知识库辅助工具，另外它也没有多设备同步之类的功能——如果你要的是一个跨平台的稍后阅读中心，可能 Cubox 那些成熟应用更适合你。这个插件只适合坐在电脑前疯狂查资料的人用。比如这几个月我自己用这套工作流，就确实省下了不少低效复制粘贴的时间。

如果你也有类似的困扰，可以去 [Chrome 应用商店](https://sspai.com/link?target=https%3A%2F%2Fchromewebstore.google.com%2Fdetail%2Feverything-to-notebook%2Fninggjblhniabhjnoojcgbpldfcadglp%3Fsource%3Dclyde%26source_platform%3Dsspai)或 [Edge 扩展商店](https://sspai.com/link?target=https%3A%2F%2Fmicrosoftedge.microsoft.com%2Faddons%2Fdetail%2Fe2n%25EF%25BC%259A%25E4%25B8%2580%25E9%2594%25AE%25E5%2590%258C%25E6%25AD%25A5%25E8%2587%25B3-notebooklm-%25E4%25B8%258E-no%2Fidadmfliapdijibcbfeggfhgcnhjbidg%3Fhl%3Dzh-cn%26source%3Dclyde%26source_platform%3Dsspai)下载一试。

SubMask：看剧练听力的正确方式
------------------

[@桌沿奇思](https://sspai.com/u/379wzx2e)：

我们从小就对一种锻炼外语听力的方法耳熟能详——看剧。方法虽然广为流传，但由于大部分视频都是双语字幕，我一直对此持怀疑态度：有多少人真的通过看剧「磨耳朵」成功了呢？

双语字幕做错了什么吗？语言学家早已针对该话题开展过研究，并得出相关结论：

> 大多数双语者对优势语言——通常是母语——的文字加工更加快速、自动且具有情绪联结，这种优势主要来自熟练度、使用频率、习得年龄和生活经验。

这意味着当我们看到视频里的双语字幕时，我们大脑很大程度上会「忽略」中文以外的字幕，因为我们阅读中文的速度远超外语。所以如果你想真真切切地锻炼听力，关闭字幕似乎是一个更好的选择。

然而，现在大部分视频的字幕文件都是与视频文件同步烧录导出的，这意味着无法单独关闭字幕。这给我带来了很长时间的困扰——既想通过看视频锻炼外语听力，却又不得不看双语字幕，而看双语字幕则意味着我基本没法真正锻炼到听力。

借助 AI 的力量，我开发了一款完全免费、适用于 Chrome 和 Edge 浏览器的插件 **SubMask 字幕遮罩**。

我在它的陪伴下笑泪交加地看完了《小谢尔顿》第 7 季。我非常喜欢 SubMask 以下特点，和大家分享：

**遮罩会影响观影体验吗？**

完全不会！遮罩有 3 种模式，我最喜欢的是「流光玻璃」，会以一种类似 Apple Liquid Glass 的形式遮住字幕，这样既保证我们看不到文字，视频画面也依然会透过来，不会打破我们观影的沉浸感。

![](https://cdnfile.sspai.com/2026/07/19/c3c999f14e5f0ee0525f1a178e47ad66.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

**担心总是要拖动遮罩吗？**

可以一键吸附！设置菜单里有一键吸附功能，直接将遮罩吸附到视频的正下方区域，免去拖动的麻烦。

![](https://cdnfile.sspai.com/2026/07/19/4cf4e912bb0c013c452c74ddd6b8b9d4.gif)

**有几句听不懂想回去看看字幕？**

一键开关搞定。直接点击键盘「H」键，遮幕会暂时隐藏，配合键盘「 ← 」即可回到视频的前几秒，看看主角们究竟说了什么。等学习完毕，再次点击「H」键，遮幕就会重新优雅返场。

![](https://cdnfile.sspai.com/2026/07/19/9c1fdfe4606f0e7680f2c3e30fa94a3b.gif)

**想拖动进度条、怕遮罩挡住？**

我已经考虑到这点了，因为字幕通常都在视频正下方，遮罩开启后很容易遮挡播放控件，因此我专门设计了「鼠标穿透模式」。开启后，鼠标经过遮罩时，除了「穿透模式开关键」以外，遮罩剩余区域会自动消失，我们便可以无痛调节进度条。

![](https://cdnfile.sspai.com/2026/07/19/097f61fa1348cfc2f983a5c2af931ab8.gif)

在此还想分享下关于名字的小巧思：SubMask 的名字取自「Subtitle + Mask」，合并之后的遮罩（mask）正好把字幕（subtitle）遮住了；而「Sub」作为前缀正好有「下方」的意思，也暗示了遮罩会出现在视频的下方。

你可以在 [GitHub](https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fdeskside%2FSubMask%3Fsource%3Dclyde%26source_platform%3Dsspai) 或 [Edge 扩展商店](https://sspai.com/link?target=https%3A%2F%2Fmicrosoftedge.microsoft.com%2Faddons%2Fdetail%2Fsubmask-%25E5%25AD%2597%25E5%25B9%2595%25E9%2581%25AE%25E7%25BD%25A9%2Fekgpgdkgajiamcjegmgemljcldcjaaao%3Fsource%3Dclyde%26source_platform%3Dsspai)下载体验 SubMask。希望大家享受插件，祝学习愉快！

只译：外语内容双语读
----------

[@空中猎手](https://sspai.com/u/xdp722y5)：

[只译](https://sspai.com/link?target=https%3A%2F%2Fgithub.com%2Fairhunter%2FOnlyTranslate%3Fsource%3Dclyde%26source_platform%3Dsspai)并不是从零开始的项目，它基于开源扩展 FluentRead（流畅阅读）开发。在保留 FluentRead 核心网页翻译能力的基础上，我重点补充了视频字幕翻译、本地 EPUB 阅读器、识文或全页范围切换，以及更精简的设置体验。项目使用 WXT、Vue 3 和 TypeScript。

先讲讲网页「识文」功能，一个我在自己使用和修改扩展的过程中，逐渐明确下来的一个需求：我大部分时间是在浏览帖子、专栏和长文章，这些页面里真正需要认真阅读的是正文，至于导航条、菜单、标签、订阅按钮和其他操作元素，我通常并不关心它们是否被翻译；另外，对于大段外语文字，单独看一句话或一小段并不一定有障碍，长时间在脑中理解和转换却会不断消耗注意力，这个时候我需要的不是把页面上的每个词都换成中文，而是让正文的阅读负担降下来。

在这类场景中，「识文」模式会优先寻找正文、帖子和评论等主要阅读区域，尽量让导航、按钮和侧栏保持原样。它更适合文章、博客和长内容，也更接近我实际需要的「阅读模式」。如果你需要阅读文档、论坛、后台或信息密集的工具页面，或者页面里的界面文字的确是内容的一部分，只译同时也保留了「全页」模式，用来处理更多可见文字，也可以作为「识文」出现漏翻时的回退选项。

显示方式上，只译同样分为「双语对照」和「仅译文」。需要核对原文或学习语言时，可以让译文跟在原文后面；只想连续阅读时，则可以只保留译文。

![](https://cdnfile.sspai.com/2026/07/26/article/38b8a6c26a82c63e8c6da18226b8da14.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

视频则是第二个被加入只译的场景：字幕翻译和网页段落翻译看起来相似，实际面对的问题却不同。网页内容通常是相对稳定的，字幕则会随着播放进度不断变化。如果逐条临时请求，容易跟不上播放；如果一次处理太多，又会增加等待时间。字幕还需要保留上下文，否则同一个词在不同语境中很容易得到割裂的结果。

只译会读取网站提供的原字幕，按上下文分段翻译，并根据播放位置显示双语字幕。本地缓存用于减少重复请求和来回拖动进度条时的等待。目前主要支持 YouTube、Udemy、Coursera 和 Khan Academy。需要注意的是，只译不负责语音识别，视频必须已经提供扩展能够读取的原字幕轨道，没有字幕的视频暂时无法凭空生成字幕。

![](https://cdnfile.sspai.com/2026/07/26/article/6b8e781122c31abab849353375f17ae9.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

我希望它保持的是「看视频」的状态，而不是把视频内容先导出、处理，再放进另一套工具。翻译应该跟着播放发生，原字幕和译文也应该可以同时核对。

最后，只译也支持本地 EPUB 阅读。一般而言，网页和在线视频至少有一个天然入口，但本地电子书通常意味着另一套应用、另一份设置和另一种阅读习惯。所以我后来在扩展里加入了一个 EPUB 阅读器，你可以导入本地无 DRM 的 EPUB，在浏览器中按章节滚动阅读，并保存书架、阅读进度和位置书签；进入章节后，可以沿用网页场景中的双语或仅译文显示方式。书架、进度和书签保存在当前浏览器配置中，不需要注册只译账号，也没有云端书架。

![](https://cdnfile.sspai.com/2026/07/26/article/0c3bee90faf064ff2cd4fbc02c6ed864.png?imageView2/2/w/1120/q/90/interlace/1/ignore-error/1/format/webp)

值得一提的是，导入的 EPUB 文件本身不会上传，但开始翻译后，需要翻译的章节文本会发送给用户选择的翻译服务。移除图书会同时删除对应进度和书签；卸载扩展或清除扩展数据，也会失去本地书架。EPUB 阅读器目前仍是 Beta，只支持本地无 DRM 的 EPUB，不支持 PDF、MOBI 或受 DRM 保护的图书，也没有云同步、笔记和 AI 内容分析。我暂时不想把它做成一个大而全的知识管理系统。

最后聊聊翻译。翻译的质量、速度、隐私和费用之间，很难存在适合所有人的唯一答案。只译提供微软翻译、Google 翻译和 Chrome 内置翻译等选项，也预设了 DeepL、OpenAI、DeepSeek、Gemini、Claude，以及兼容 OpenAI Chat Completions 的接口。免配置服务可以直接使用；AI 服务需要填写对应的 API Key，并遵循服务商自己的计费和隐私规则。

只译本身免费、开源，不要求注册账号，也不绑定订阅。设置、缓存和电子书书架保存在浏览器本地，项目方不收集扩展使用数据。使用在线服务时，待翻译文本仍然会发送给所选服务商，这一点不会因为扩展开源就自动消失。

只译目前以 Chrome 为主要支持平台。浏览器内部页面、扩展商店和其他安全受限页面不允许普通扩展运行；复杂网页和持续变化的动态内容也仍可能出现漏翻或排版问题；字幕翻译依赖原字幕，EPUB 阅读器仍处于 Beta，识文模式也不可能准确理解所有网站的结构。

如果你平时会认真读外语文章、课程字幕或本地 EPUB，也愿意尝试一款仍在完善中的工具，可以在 [Chrome 应用商店](https://sspai.com/link?target=https%3A%2F%2Fchromewebstore.google.com%2Fdetail%2F%25E5%258F%25AA%25E8%25AF%2591%2Fhiajidipndfdngigicngbkhbjolggifi%3Fsource%3Dclyde%26source_platform%3Dsspai)下载安装只译。
