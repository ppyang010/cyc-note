最近注意到 Reasonix 用 Go 重写了一版。说实话第一反应是有点意外:这两年 AI 编程工具的”出厂默认”几乎是 Node/Python,一个 Go 重构的消息反而显得逆流。但转念一想,如果你真在终端里长期重度用过这类 Agent,会觉得这个方向其实早该有人走。

我做开源项目 [deepx-code](https://link.zhihu.com/?target=https%3A//github.com/itmisx/deepx-code)(DeepSeek 原生、兼容 OpenAI 接口的终端编程 Agent)时,从第一行就是 Go。不是因为情怀,是被几个具体问题逼的。借 Reasonix 这个由头,把”AI Agent 为什么适合 Go”这件事掰开讲讲——也算给在做同类工具的朋友一点参考。

更巧的是,这一版 Reasonix 还集成了**代码图谱(codegraph)**——而 codegraph 恰好是 deepx-code 早就内置、并且我反复打磨过的一块。是不是借鉴了 deepx 的思路,我不知道,也不好乱讲;但”Go 重构 + codegraph”这个组合同时出现,至少说明一件事:**这两个选择背后的工程直觉是相通的**。下面正好把这两件事一起聊了。

> 先声明:Reasonix 重构的内部理由、codegraph 怎么实现的,我都不清楚,这里不替它脑补。下面讲的是我自己踩出来的、Go 在这类场景下的真实账。

### 一、分发:`curl` 一行 vs `npm install` 的连环坑

AI Agent 是命令行工具,用户期望是”装上就能用”。

Node 系的现实是:用户得先有对的 Node 版本,然后 `npm install -g`,然后大概率撞 node-gyp、原生模块编译、`EACCES` 权限、全局 PATH 这几座大山中的至少一座。Python 系更别提,虚拟环境 / `pip` / 系统 Python 污染,劝退一片。

Go 的答案简单到无聊:**编译成一个静态二进制,丢过去就能跑**。deepx 的安装就是一行:

```text
curl -fsSL https://raw.githubusercontent.com/itmisx/deepx-code/main/scripts/install.sh | bash && exec $SHELL
```

macOS / Linux / Windows 三平台同一套思路,没有运行时,没有依赖树,没有”我这能跑你那不能跑”。对一个想让人随手试一下的工具来说,这一步的转化率差距是致命的。

### 二、长会话省钱:Go 让”缓存友好”这件事能做扎实

AI Agent 的成本大头是**重复发送的上下文**。每多聊一轮,前面整段历史又要随请求发一次。解法是供应商的前缀缓存(prompt cache)——只要请求前缀字节级一致,命中部分按零头计费。

但”前缀字节级一致”这条件,对工程实现要求很高:你得无损、稳定地序列化整段会话历史,system prompt、tool\_calls、tool results、reasoning\_content 一个字节都不能飘。Go 的强类型 + `encoding/gob` 在这件事上太顺手了。deepx 用 gob 把完整历史落盘:

```text
~/.deepx/sessions/<sha1(workspace)[:16]>/
├── history.gob        # 二进制完整历史,重启无缝续接
└── YYYY-MM-DD.jsonl   # 纯文本日志(给 Memory 搜索用)
```

效果是实打实的——一个真实长 session:**41,591 tokens 里 41,472 命中缓存,~99%**。DeepSeek 对命中缓存的输入按未命中价的几十分之一计费,长跑几乎不为重复上下文重复付费。

这种”前缀稳定性”在动态类型语言里不是做不到,而是容易飘:序列化顺序、字段默认值、版本升级后的 schema 漂移,任何一处抖动,缓存前缀就断了,钱就白花。Go 把这类问题摁在编译期。

### 三、本地优先:不是每件事都得喂给 LLM

很多人忽略的一点:一个好的 Agent,**应该尽量少调用 LLM**。能在本地用确定性逻辑解决的,就别花 token、别等网络往返。

Go 的零运行时、原生并发、能直接链 C/ONNX 的特性,让”把活留在本地”变得很自然。deepx 里有几处都是这个思路:

-   **模型路由本地做**:消息发来,本地关键词匹配 + 长度判定,瞬间决定起手用 flash 还是 pro。零延迟、零 token、零网络:

```text
含 "重构 / refactor / architecture / 调试 …"  → 升 pro
  长度 < 100 字符                                → flash
  长度 > 500 字符                                → pro
```

-   **离线图片 OCR**:内置 PaddleOCR(经 ONNX runtime),丢一张截图本地就把文字抠出来,不走云端多模态 API——这块我单列在第五节细讲。

一句话:Go 让你有底气把更多确定性工作收到本地,而不是事事都甩给大模型。

### 四、单说 codegraph:为什么这块 Go 是降维打击

既然 Reasonix 这次也上了 codegraph,这块值得单拎出来讲——因为它最能体现 Go 的优势,也是 deepx 我打磨最久的地方。

代码图谱要解决的核心问题是:模型问”这个函数被谁调用 / 这个接口谁实现了 / 我改这里会影响哪些地方”,**怎么给出准确答案**。绝大多数工具的做法是满仓库 grep 字符串,再把一堆候选喂给模型自己猜——既费 token,又会因为同名符号、注释、字符串误命中而出错。

codegraph 走的是符号级的真解析:

-   **跳定义 / 找调用 / 接口实现 / 影响面分析**,返回的是结构化的符号关系,不是文本匹配的碰运气;
-   **Go 项目直接挂 `go/types`**——这是官方类型系统,解析精度等同编译器,跨包、泛型、接口满足关系都算得准。这一步几乎是 Go 写 Go 工具的”主场红利”:你拿到的是和 `go build` 同源的类型信息,别的语言要么自己造轮子,要么精度打折;
-   **其它语言走 tree-sitter** 做白名单式抽取,在精度和通用性之间取平衡。

效果就是:模型问”影响面”,拿到的是准确的调用图,而不是 50 条 grep 结果让它自己脑补。准、快、还省 token——这三点对一个按上下文计费的 Agent 来说,直接关系到好不好用、贵不贵。

所以看到 Reasonix 也补上 codegraph,我是真高兴的:说明这条路被更多人认了。至于实现层面谁更扎实,欢迎大家都拉下来对比着用,代码都摆在那。

### 五、本地 OCR:我赌它是下一个会被”认可”的方向

前面第三节带过一句离线 OCR,这里想单独展开——因为这是我接下来重点押注的方向。

现在的痛点很具体:你截一张报错、一张设计稿、一张表格丢给 Agent,主流做法是走云端多模态 API——慢、要联网、按图计费,还得把你的截图传出去。deepx 的选择是反过来:**内置 PaddleOCR(经 ONNX runtime),图片不出本地就把文字抠出来**。这件事 Go 干起来很舒服:cgo / purego 直接链原生推理库,单二进制里就把模型推理带上了,用户不用额外装 Python、不用配 CUDA、不用起服务。

它的门槛也恰恰在这:OCR 不是几行 markdown 约定就能复刻的东西,要处理模型权重、图像预处理、ONNX 推理、跨平台编译——是块**工程硬骨头**,这正是它能成为护城河的原因。

而我更想做的是它的”下一步”:

-   **截图直接进上下文**:贴一张 UI 截图,本地 OCR + 版面分析抽出结构,模型直接拿去还原布局 / 定位报错,不再让你手敲;
-   **表格、公式、手写体**的本地识别,覆盖更多”图里有信息但模型看不见”的场景;
-   把”读图”做成和”读文件”“跑命令”平级的一等本地能力——**能本地确定性解决的,就不花 token、不走网络**,这和全篇的主线是一致的。

所以话说在前头:如果哪天 Reasonix 也补上本地 OCR,我大概率还是那句话——**高兴,说明方向对**。codegraph 走过一遍的剧本,OCR 也欢迎再走一遍,代码一样都摆在仓库里。先行一步的好处,是你永远在定义”下一步”是什么。

### 六、并发:多步任务的两套调度,写起来不别扭

Agent 干复杂活,要么是**顺序多步**(一步步勾待办),要么是**可并行的独立子任务**(拆成 DAG 派并发子 agent)。后者在 Go 里就是 goroutine + channel 的本职工作,不用 async 染色、不用 event loop 绕弯。deepx 两套都做了:顺序 Todo 清单 + 并发 Plan DAG,按任务形状选。

### 写在最后

Reasonix 选 Go,我不知道它内部怎么想的,但从”终端 AI Agent 这个品类该长什么样”来看,这个方向我是认同的:

-   分发要轻——单二进制,`curl` 一行;
-   成本要省——缓存友好,长会话不为重复上下文反复付费;
-   本地要强——能不调 LLM 就不调,路由、OCR 都留在本地;
-   代码要懂——codegraph 符号级解析,Go 挂 `go/types` 精度等同编译器;
-   并发要顺——goroutine 天然适配多步 / 并行任务。

这几条,恰好都是 Go 的舒适区。Reasonix 这次的”Go + codegraph”组合,某种程度上是同一份工程直觉的又一次印证。
