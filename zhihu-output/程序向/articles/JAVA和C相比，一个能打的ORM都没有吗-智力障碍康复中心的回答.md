构建一个优雅的orm最关键的4个语言特性：

1、linq

2、表达式树

3、扩展方法

4、运算符重载

  

这些语言特性java都没有，所以java的orm除了用反射把实体类更换成表和字段以外。做不了什么事情。逻辑联接只能起一堆生硬的英文名字的方法。通过大量的点和括号拼在一起。显得十分笨拙 。

c#利用以上特性几乎实现了sql语法完美还原。再复杂的sql也可以转换成具有静态检查重构能力的纯c#代码。从codefirst的设计思想来说，c#做到了编译通过，即运行通过。

而mybatis在内的所有java orm框架还做不到复杂场景的0sql。或多或少都会在代码中夹杂着许多原始sql或用于构建sql的“字符串”，这些不具有编译器感知能力的字符串，则是失去了静态语言优势的落后代码。写错了在编译时检查不出来。却会在运行时出错。是产生bug的罪魁祸首，不能一键重构，需要挨个肉眼识别，心智负担相当大。
