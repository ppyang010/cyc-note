分三种情况来讨论这个问题：随便写写（或一般水平的认真写），给足资源认真写，资源限定（时间和人手）下认真写。范围也扩大点，把cpp也拉进来讨论。同时也讨论下内存占用。

（1）随便写写。

简单的小程序，java，csharp和cpp，性能差不多，可能有的 cpp 会好些，有的 java会好些，有的 csharp 会好些。我曾经比较过 float 数组上的一些密集计算，结果吓我一跳，java 性能高于 cpp 和 csharp。分析发现，java 的 c2 优化，会对代码做自动向量化。csharp 不会，手动加上 simd 后，性能比 java 略高。

当然，如果是触发到java 没有值类型这个大缺陷的场景，就算随便写写，csharp和cpp的性能也会暴打java，性能高十倍都常见。

如果是复杂一点的程序，随便写写，cpp 搞不好直接段错误了。java 程序和csharp程序，应该性能差不多。

内存占用上，csharp 会比java 要少一些或少很多。cpp 最少。

这种情况下，可以经验的认为 csharp，java 执行效率一致，cpp 一部分概率一致，一部分概率没写完或直接挂了。

（2）给足资源认真写

毫无疑问，各种骚操作全上，无论性能还是内存占用，cpp都是大王。个人经验，大概可以认为，性能上，cpp:csharp:java = 10:8:5（越大越好）。内存占用上，cpp < csharp < java。这也是为什么，很多基础设施用cpp写的原因。开发资源足够的情况下，可以选择 cpp。

回到题目本身，这种情况下，可以经验的认为，csharp 执行效率比 java 高 30%。

（3）资源限定条件下认真写

这种情况下，往往 csharp 是第一。给定资源，csharp 开发最快，可以有闲暇来梳理架构、针对应用场景设计特定的数据结构和算法（这个很重要，因为常见库的算法和数据结构针对的是通用场景，针对特定情况微调，性能能大幅度提升）。cpp 的会忙于写代码，调bug。java 的也会忙于写代码，没时间考虑这些，就算有空考虑，可用的手段也少很多。

讲两个我的实战经历。

a，开发数字油画软件，就是把一幅图像变成数字油画的编码图（颜色聚类后向量化）。七八年前的事情。市面上有款竞品是 cpp 开发的，已经迭代好多版本了。我直接上的 wpf，全C#开发，那时还没 simd。底层算法全手写，不用opencv什么的。全部开发完，大概也就一个月时间，无论是一副图像的处理时间还是处理效果，都比竞品要好。也就是，一个月的时间，干了三件事：功能开发、性能调优、效果调优。cpp 程序员，估计就没这时间和心情去干这么多事情了。

这种程序，就是 java 最不擅长的地方。没有值类型，java 处理 color 极其难，byte 是有符号的这个设计，处理 color 时就知道多二比多反人类了。new 一个 color 对象的话，直接在堆分配，性能拉胯的同时会爆内存。new 一个数组在数组上操作，代码会很繁琐。

b，AI 应用。甲方要求是处理一例的时间低于1分钟。竞品是某CV四小龙公司，我猜测是 python+cpp，也有可能有java。我这边是 csharp+python+cpp。竞品优化了一个月，没达到目标。我们当时的性能是处理一例2分钟，销售吹nb说我们处理一例8秒，客户要测。俺直接晕了。用了俩天时间，优化csharp部分代码，unsafe 打开，指针用上，并行库用上（现学现用），异步用上（gpu做inference的同时，cpu不能闲着），把硬件资源吃干抹净）一通骚操作，优化到了一例5秒，搬到客户那边，用他们数据测，一例不到2秒。

也就是说，在资源有限的情况下，时间很紧，csharp 因为开发最快，优化手段繁多，往往会是最快的那个。这种情况下，也可以经验的认为，csharp的执行效率比java高30%，甚至更多。

总结：

（1）随便写写或团队水平不够时，java 和 csharp 执行效率半斤八两，cpp 由于开发太慢，太难，直接pass。

（2）资源足够团队水平够高时，cpp 是绝对的王者。csharp 和 java 都不够看，但 csharp 要比 java 表现好的多，可以经验认为，执行效率高30%甚至更多。

（3）资源不够但团队水平够高时，csharp 是王者，暴打cpp和java 可以经验认为，执行效率比java高30%甚至更多。

现实是：

（1）这种情况最常见，内存又是白菜价，java的 先发优势太大，.net 想翻身不容易；

（2）一般是大公司大团队；

（3）一般是精英中小团队。

在国内环境下，csharp 不是好的就业语言，只能说是优秀的创业语言。顺便再提一句 blazor，对产品 0-1 阶段来说，blazor 真 tmd 是神器。

* * *

单从技术来说，还是那句老话，.net 和 java 比性能有点欺负人，.net 性能优化的目标是 cpp，随着版本升级，优化手段也越来越多。

很多情况下，.net 程序性能底下的原因是，它的最初定位是对标 java，把 java 的坏东西学了不少过来了，各种常用库设计的非常复杂，继承体系一层套一层，用得上的用不上的属性、事件一大堆。功能点太多，好多实现是胡乱写的。所以很多程序，明显的比 cpp 要慢不少。.net 6、7 可以看见，开发团队在想各种办法优化底层库。
