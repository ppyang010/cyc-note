当然不是，Go 初始静默状态内存消耗什么的都要比 Java 小，但是带了载之后，较差的编译优化粗糙的内存模型和垃圾回收带来的副作用就体现出来了。

-   为了保持较高的编译速度，很多优化做不了就是做不了，这都不考虑那些需要 PGO 的优化，JVM 有 JIT，Go 拿什么拼~~
-   为了保持低 STW，三色标记+无压缩无复制，内存碎片化会很严重；gc 不分带，每次都全图遍历成本也高；
-   吹破天的 goroutine，stack 永远只增不减（好，这个我说错了，可以减），现在 JVM 有 Loom 了，跑起来还真说不好谁省内存，何况 Go 这边流行把东西往栈上怼，一堆大 struct 复制来复制去的；Loom 虽然会复制整个栈，但是 JVM 那边流行往堆上怼，栈干干净净的；

要性能还是去看看原神编程语言吧
