mysql 细节不太了解, PG 的细节比较了解, 两者实现细节应该差不多的, 毕竟都是工业级的关系数据库.

经评论同学指正，实际上 innodb 默认是聚集索引，这个和pg 的heap表引擎实现的索引是有差异的，一个是索引和数据在一个文件，另一个人分离的。

PG 的默认索引是 B+树的变种 B-Link树, 用于实现 B+树性质的情况实现高效的的并发控制.

数据库中 index 存在的本质是为了在更为高效但空间小的内存中实现能够提升查询性能的数据结构,从而能够达到加速整个query查询性能的目的. 这样的话也就意味着 有限的内存只能保存少量的数据, 大部分的实际数据肯定都会在磁盘上.

B-Link树创建的时候肯定是需要指定具体表的某一列的, 以这个列为索引键 构建 B-Link树, 索引键对应的value保存的是指向这个索引行所在的数据文件的tuple位置. 当要 加载索引文件到内存时, 实际只会有**索引键 以及 存储于叶子结点的value (数据行所在的数据页的位置)被加载到内存中**.

当我们的query是 index-only scan , 比如只查询索引键 \`select id from t where id = 10;\` id是 t 表的一个索引键时, 就不需要加载实际的 t表的数据了.
