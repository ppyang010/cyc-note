这就是有栈纤程fibre

和

无栈协程coroutine

的区别

无栈有传染性

需要用户手动标记 async 关键字加以区分，大部分是 async 关键字，kotlin用suspend

所有用到了 async 方法的方法，都要声明成 async，同时还需要配合 await 操作 async 方法

所以无栈比有栈至少多了两个关键字 async/await，开发时候对人的思维负担就更重了

你需要跟普通程序员去解释什么是 async 什么是 await，工作时候这可不是什么好事，因为你在教育程序员的时候，往往是它看你恶心，你看它讨厌，相看两生厌的状态，毕竟搞技术的又不是什么美女，呆久了你烦他也烦，为了这种事凑一起，多不值

有栈就轻松多了，没有这事，当然内存等资源会多吃一点，宝马和奔驰当然比本田和丰田更耗油，因为它多做了事，但是比起人工的额外开销，这种设计显然更讨喜，让机器难受一点，然后让人舒服一点，何乐而不为？

对于async/await我唯一能理解的就是 swift，因为swift不仅要替代c++，它同时还要取代c，所以有些东西不能做得那么底层，而苹果已经摆明了要用swift 替代 c++，obj c 和 c，虽然 async/await 多了两个关键字，但是为了不写 c，那还是值得的，类似的 swift 比起 c 还多了 weak，class等关键字，用 swift 平替 c & c++，总体来说还是相对更简单滴

至于其他的，仅在应用层面使用的编程语言，设计出来 async/await 就属于错误的设计，因为有栈的实现完全可以让用户不做这事，多一事不如少一事，工具的操作还是越简单越好，当然前提是都能实现目的，多数资本也不会有兴趣在这种事情上投资，投资程序员去搞搞搞是很容易坏事的，能交给机器解决的，都应该交给机器解决掉，人毕竟是人，人出错的概率比机器要大得多，不能太指望人
