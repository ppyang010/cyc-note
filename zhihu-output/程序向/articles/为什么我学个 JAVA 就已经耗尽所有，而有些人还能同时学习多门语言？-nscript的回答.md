用上的才学，用不上的学了干什么。当你发现，要解决一个问题，需要学习A语言时，学习A语言根本不花啥精力和时间，并且反馈很快，马上就有解决问题的成就感，这种学习是最高效的。瞎学，跟风学才是最浪费精力和时间的。

工作中用了有一二十种语言了，基本都是这个流程：出现了需要解决的问题 -> 发现A语言可以解决它 -> 判断最小学习范围，学习 -> 解决问题 -> stop。这个过程，根本没痛苦可言，全是享受。其它时间，就学些共性的跟语言无关的东西，几十年不过时的。

无目的学习这件事情，不要把他当做好事情，要当成坏事情，尽量避免的事情，实在没事干时才可以做的事情。如果是为了找工作，那倒无可厚非。不能是强迫症。就好比看网文，非把知名的网文看完不可。看小说，也非把古今中外出名的小说看完不可。不累才怪。

学一门语言的目的，不是把它搞的通透，再做出伟大的产品出来。抱着个目的去学习的，基本上都达不到目标。一般是反向的，要做个什么东西出来，有啥不会的再补课，学到能解决当前问题的程度就够了。如果决定走某语言的专家路线，或者打造个人专家的ip，再考虑深入。

* * *

回顾俺的语言学习过程，大学里学的 c，matlab，fortran，fortran 学完就忘了，matlab 还有一丁点印象。c 能看懂代码写点小程序。当年为了写网页学的vbscript和sql，[asp升级成asp.net](https://link.zhihu.com/?target=http%3A//xn--aspasp-kd5jy09g907c.net/) 后学了csharp，搞gis学了java，搞网络仿真学了tcl和cpp，去研究各种协议。为了分析动辄几十G的日志去研究awk和sed，为了在linux下快速开发学了mono和python，这差不多是04年前的事情。为了做flash开发学了as3，为了把as3程序迁移到html5上，学了haxe（这件事发生在2012年，haxe和as3很像，这个迁移是成本最低的），为了把类似的程序迁移到手机上学了android开发。为了快速出算法，学了csharp unsafe 开发，为了把算法卖给客户，学了点 delphi，vb（很多客户程序是 delphi 和 vb 写的），搞人工智能又捡起来python。写web程序离不开js，嫌js不好使又学了ts。嫌写java麻烦，学过kotlin，后面觉得太杂，又后退到 java。跟风学过ruby，haskell，fsharp，clojure，基本都忘光了。为了找一个好的开发快的高性能开发语言，dlang，golang，swift 也都摸过，判断他们不合适俺后，就放弃了。

现在回顾，对俺而言，水平的提升跟学语言，学各种库没太大的关系，关键还在于解决问题和刻意练习。真正让俺技术水平短期内大幅度提升的几件事：

1, 十七八年前一个项目，把网络协议模拟库ns2给改成实时仿真程序。最近经常在知乎上刷到问题，怎么按ms调度事情。当年做的就是这样的事情，要把模拟库（模拟时间和真实时间可以不对应）改成仿真库（模拟时间和真实时间需要对应，指定一件事情在3秒后发生，他就得在3秒后发生）。模拟的网络协议没有payload，仿真里的数据包都得是真的。用很少的设备，模拟大量的设备很好的负载。为了解决这个问题，从数据结构，算法，操作系统内核，网络协议栈等全面魔改，才顺利完成任务。用一台奔三还是奔四的电脑模拟几万个ip地址不同终端，跑在终端上的仿真程序可以跟网络上的其他程序互动，网络流量到近百M，丢包为0，事件调度的时间差异控制在ms级别。完成之后，非常有成就感。深入理解linux内核，网络协议啥的，都翻烂了。日志动不动几十个G。语言全是现学的，核心开发用cpp，脚本用tcl。分析日志，用python+awk，ui配置用mono（winform/gtk#）。研究离散时间模拟的核心数据结构什么什么优先队列名字已经忘记了，直接魔改了。几个月的时间，把操作系统，计算机网络，cpp，仿真，日志分析，随机数生成都研究了个透。

2，做flash开发时，为了提升开发速度，同时降低生成文件的大小，对 flex 魔改，把它的数据绑定部分给拆出来，ui库丢弃，自己借助数据绑定和底层绘制api弄一套gui。搞出来之后，就对各种ui框架无所谓了。这套东西，先后写了as3的版本，写了cpp的版本，写了csharp/winform的版本，csharp/wpf的版本，写了haxe的版本，写了ts/canvas的版本，写了java的版本。主要收获有三：（1）对各种ui效果看一眼就知道咋绘制出来的。（2）理解了线性代数。最开始写的时候，很多地方用的三角函数，后面写的时候，用线性代数，才发现，我十十，这么简洁，然后把线代给捡起来了。以前要写一千多行的，慢慢二三百行就能解决的。（3）理解了正交分解的概念。《程序员修炼之道》里提的正交分解，真正理解不容易。所谓正交分解，就好比给一个空间建坐标系，一个三维空间，你给搞成六维的问题可不就麻烦多了。写gui库，不懂正交分解，基本上是灾难。懂了之后，去看各种程序问题，架构问题，即使是非gui的，也能一眼把握住重点，以及如何分解。

3，做csharp开发时，坚持尽量不用opencv，把opencv里的算法用csharp翻译，然后，再跟opencv程序pk性能，每次都要优化到opencv的70-80%再住手。结果就是，掌握了各种风骚的查表操作技巧，还有csharp里很多骚操作。用csharp交付和验证了很多大家认为应该用cpp开发的项目和产品了。

现在，问题来了。flash开发，我就会点as3，数据绑定，不会 flex ，也不会 flash 的那些组件，你说我是精通它还是不精通它？csharp开发，linq我都不会，[asp.net](https://link.zhihu.com/?target=http%3A//asp.net/) 能写 hello world，wpf，winform 也能写hello world，控件都不熟悉。aop也基本不用，表达式树也不知道是啥东东，异步也用的很少，面试肯定过不了。这是啥水平？

正在学习和研究的事情：（a）用csharp来翻译openai的语音识别模型whisper，打算用这个真实而又有用的项目验证下csharp simd和ilgpu的能力，预计代码量在1w行左右，github上有cpp版本可参照，cpp版本用了simd但是没用gpu加速，俺计划上gpu加速；（b）出海是大趋势，一定会遇到语言问题。各种文字，怎么输入，怎么显示也蛮好玩的，不看不知道，一看全是坑。比如，bidi 问题，我测试了很多编辑器，大部分都不正常，借这个东西，同时把skia给消化掉，你看，maui什么的我又不打算学了，学习焦点放在 skia 上；（c）用 csharp 脚本做 serverless 计算，比如说，有大量的数据，100万部视频，或者1亿篇文章放在云上，用csharp写一个几百行的分析脚本，脚本驱动云端开启N个核来分析，汇总分析的结果，一个脚本文件，要解决高性能计算，自身的编译，发布，云端调度，结果汇总等等环节。这种学习和研究多有意思，又好玩，又有用，又不枯燥。
