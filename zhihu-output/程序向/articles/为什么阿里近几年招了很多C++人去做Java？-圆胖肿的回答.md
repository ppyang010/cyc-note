我前一段就在看，怎么鬼佬java都没见过的什么bio，nio和aio的概念，被国内的人，张冠李戴，强行摁在java头上

后来发现，大概率是阿里那群人干的吧

因为阿里云后来还在medium上发了一个英文文章，讲了java得bio，nio和aio，感觉就是个中译英

而java真正的io，应该是[http://java.io](https://link.zhihu.com/?target=http%3A//java.io)，java.nio（这里n是new的意思）和虚拟线程

这三个部分组成，比起复杂难懂，一堆乱七八糟概念满天飞的bio/nio/aio那些

java的概念要通俗易懂得多，用户只需要知道，io性能差，但是写起来简单，nio反过来，性能好，但是写起来复杂，用户在没有虚拟线程之前，需要在这两者之间做选择

而在有了虚拟线程之后，用户可以像io一样写简单代码，同时又能享受到nio的性能

而这些东西都封装到了框架，比如vert.x或者tomcat这些里面去搞定了，普通用户其实根本不需要知道什么乱七八糟的bio/nio/aio那些

而中文网站上满天飞的bio/nio/aio，那个给我感觉啊，就像是一个c++程序员，写unix或者linux上的软件写多了，有点走火入魔了，然后被要求写java，然后用它的那种c++的那点经验，或者说解题思路，去硬套java，就导致了这种错误文章的诞生

我不知道阿里是不是真的招了c++的人去做java

但如果是真的，或许这就能解释为什么中文网站上，出现了那么多，有着明显错误的，c++痕迹明显的所谓技术文章，这种文章真是误人子弟

讲真的，阿里对于java整个社区，没有多少贡献，其贡献不到ibm/red hat或者Google的百分之一，甚至可以说没什么存在感

阿里做了一大堆乱七八糟改版的开源软件，比如dubbo，fastjson啥的，对整个社区可以说是弊大于利

就像阿里云的maven仓库，你要做镜像，就把所有的依赖都拷贝过去就是了，你偷偷删掉一点是几个意思？搞得学生们一做作业就在问，为什么有些依赖找不到，我看了下，说你还是别用阿里云的镜像了，就用maven中央仓库的就好了，反正国内也有cdn

我在国外也罢，在国内也罢，反正看到国产的，包括阿里在内的开源，我都情愿不用，躲之不及

用了一堆麻烦事，何必自找麻烦，鬼佬的东西没有那么多kpi driven，反而都是单纯冲着解决问题这个目标去的，很少在软件里面夹带什么私货

说到这里，突然想说，阿里这种，还是行行好吧，别折腾了，你要用开源就用，别拿着人家老外开源的一通乱改之后，还说自己比人家高级多少，给同行下蛊，这才是最恐怖的事
