针对工科生群体，我认为需要掌握一种思维模式：**放弃高中时期的“白盒思维”，拥抱真实世界的“黑盒思维”**。

以我大三上学期的操作系统课程实验为例，实验一要求完成“Linux 内核编译及添加系统调用”。为了配合实验，任课老师发了一本 Linux 原理参考书，好几百页，全都是极其硬核的底层原理。

当时的我掉进了一个**错误的思维陷阱：我觉得在做实验之前，需要把书上的基础理论搞明白才可以。**

于是，在完全没有 Linux 实操经验的情况下，我抱着这本书开始硬啃，结果越看越焦虑，最后眼睁睁看着周围同学把实验都做完，找老师验收通过了，自己急得快哭了。

但现在回头看，其实那个实验根本没那么可怕。无非就是下载源码后，改几个配置文件并编译运行。为什么当时会那么绝望？

因为我被高中时期的解题思维惯性绑架了。高中的应试教育考试需要我们有一种极致的“白盒思维”，以数学大题为例，如果有 20 行解析，哪怕有 1 行没看懂，这道大题都解不出来。这种长年累月的训练让我形成了一种潜意识：**眼前出现的每一个信息单元都是致命的，必须 100% 处于自己的掌控下，搞懂底层原理，才能掌握正确的解题思路。**

但是在真实的项目中，这样的思维是比较致命的，以之前的操作系统实验为例，Linux 内核有成千上万行代码，如果沿用高中时期的“全盘掌控”的思维，非要搞懂每一行代码才能上手，大脑就会直接宕机。

“黑盒思维”赋予了我们合法忽略信息的权利，我们只需要掌握一种“安装部署”的思维即可。找到项目中的 config 文件，修改其中的部分参数，通过现成的接口实现对于这个“黑盒”系统的调用。至于中间复杂的执行过程，直接放心大胆忽略。

在拥有实操经验的基础上，再去阅读相关的理论，才能一步步把这个黑盒拆开。如果一开始就死磕“抽象概念”，最后反而啥也没学会。

基于上述的思维模式，给读工科的学弟学妹们一个建议：

想要掌握一门技术，先从项目实操开始，千万别一上来就去啃理论。

本科涉及到的大部分实验项目，不需要你有太深的理论基础，都是可以直接上手做的。从 GitHub 下载源码，照着 readme 一步步部署，遇到不懂的/报错的就去问 ai。等你真正跑起来这个项目，想要进一步优化这个项目的时候，才是你翻开理论书、慢慢砸碎黑盒的最好时机。
