做量化的人都有一个共识：全市场回测的瓶颈从来不是策略代码，而是数据工程。

拿全市场 7000 多只股票的分钟线回测来说，用远程 API 方案跑一遍，真实工作量大概是这样的：

-   **数据下载**：全市场分钟数据逐股请求，受限于频控、积分、IP 风控，实测需要 3 到 5 天。爬虫方案更不用说，批量拉取直接封号。
    
-   **数据清洗**：停牌、退市、代码变更、缺失补拉、时间排序，1 到 2 天。
    
-   **复权处理**：获取分红送转数据、推算复权因子、历史回刷，又是 1 到 2 天。
    
-   **存储设计**：选型数据库、设计表结构、建索引、批量入库、优化查询，1 到 3 天。
    
-   **指标计算**：写 MA、MACD、KDJ 这些公式，用 pandas 跑全市场遍历极慢，单次数小时，2 到 3 天。
    
-   **板块映射**：爬取概念和行业数据、构建双向索引、持续维护，1 到 2 天。
    
-   **接口对接**：Python、HTTP、Excel、AI 各自对接维护，1 到 2 天。
    

合在一起，最少**10 到 15 个工作日**才能跑通第一个全市场策略。

远程 API 方案在全市场回测场景下不是慢，是跑不通。

## free-stockdb 想解决的问题很简单：把数据工程和策略研究彻底解耦

数据更新在同步层完成，策略只读本地数据集。数据源可以换，但研究接口不变。

这个项目是一位开发者被各类数据接口折腾到忍无可忍之后，自己从头写了一个 C++ 股票专用数据库。之前他试过：

-   SQLite：数据到 6GB 就卡得不行
    
-   MongoDB：安装包 900MB
    
-   DuckDB：同步数据烦得不行
    
-   Redis：内存占了 18GB
    
-   akshare：天天封 IP
    
-   jqdata：年费几万
    
-   tushare：全要积分
    

最后干脆从头定制了一个 C++ 股票专用数据库，总大小只有**2.2MB**。

## 两分钟从零到可运行

Windows 用户从 Releases 下载发行包之后：

1.  双击运行数据更新工具
    
2.  数据自动同步到本地`./data`目录
    
3.  启动 stockdb 服务（只有 2.2MB）
    
4.  直接用 Python、HTTP、Excel/WPS、网页或 MCP 查询本地数据
    

数据完整落盘在本地，后续更新只处理变化数据。断网的时候照样可以查询、回测、计算。

### 内置的数据工程，开箱即用

使用者原本需要自己维护的东西，启动后直接就有了：

### 数据存储：Zstd 压缩，比 CSV 和 MySQL 小 3 倍以上

历史数据采用 Zstd 压缩存储，实际磁盘占用远小于同等数据量的 CSV 或 MySQL 方案。首次同步从配置的数据源获取历史数据，后续只更新增量，不走逐股逐页的远程 API 拉取流程。

默认数据集覆盖高频行情与复权，底层数据库支持任意自定义数据存储。低频率数据比如财报、宏观、资金流等，也可以按需接入同一套本地查询和计算引擎。

### 核心能力

日线、周线、月线，1/5/15/30 分钟 K 线，tick 级数据按需支持。价格、成交量、成交额、换手率、估值、市值、ST 等常用字段全都有。前复权、后复权、不复权和原始复权因子查询都支持。股票、ETF、行业和概念板块的组织与双向查询也是内置的。

本地存储意味着没有远程查询延迟，研究和回测不受远程 API 并发配额影响。还可以配置成局域网服务，多人协作、分布式回测。

**批量查询与计算**

```text
# 批量获取行情数据
result = get_data(
  code=7000_codes,     # 7000+ 股票/ETF
  start=any_start,     # 任意时间周期
  end=any_end,
  frequency=any_frequency, # 分钟/日/周/月
  fq=any_fq,        # 前复权/后复权/不复权
  fields=any_fields,    # 任意字段筛选
  as_df=False/True    # 返回 list、dict 或 DataFrame
)

# 批量计算技术指标
result = zb.get(
  name="ma,kdj,macd,....", # 39 种指标 + 5 种指数
  codes=7000_codes,    # 单股/批量/全市场
  start=any_start,
  end=any_end,
  frequency=any_frequency,
  fq=any_fq,
  n=["5,10,20",None,"12,26,9"], # 每个指标独立参数
  cross="with_value"   # 原始指标/金叉信号/二者同时返回
)

# 板块双向查询
result = bk.get(
  x=code_or_board_or_codes,# 股票代码/板块名称/代码/批量股票
  category=0-3,      # 概念板块/申万一级/二级/三级
  fields="code,name,symbols"
)

```

`get_data()`面向全市场、长周期和字段筛选；`zb.get()`面向 39 种技术指标和 5 种指数计算；`bk.get()`用于股票与行业/概念板块的双向映射。数据和计算始终在本机服务侧完成，研究代码不需要反复把全市场数据搬到远程 API 或临时 DataFrame 里。

**内置 39 种技术指标**：

-   趋势类：MA、EMA、SMA、WMA、DMA、EXPMA、TRIX、DMI、DFMA、BBI
    
-   震荡类：MACD、KDJ、RSI、WR、CCI、PSY、BIAS、ROC、MTM、DPO
    
-   通道类：BOLL、KTN、TAQ
    
-   量价类：OBV、VR、EMV、MFI、CR、MASS
    
-   综合类：ATR、ASI、BRAR、XSII、STD、SUM、HHV、LLV、REF
    

5 种指数计算方法：等权、流通市值加权、成交额加权、成交量加权、总市值加权。

**五种调用方式**：

MCP 协议是自实现的，不需要额外安装 MCP SDK。AI 工具通过 MCP 连接后可以直接调用`get_data()`、`zb.get()`、`bk.get()`查询本地行情、计算指标和分析板块。

**数据源可控，不绑定任何一家**

数据源是输入，不是产品的唯一依赖。你可以：

-   在`sync_url.txt`里切换到自己的同步节点、内网服务器或网络共享目录
    
-   用`file://`或本地目录离线同步已归档的数据快照
    
-   通过本地写入接口接入其他行情来源，补充或更新自有数据
    
-   保留本地数据快照，在任何没有外网、没有 Token 的环境里继续查询与回测
    

数据源服务的可用性变化不会让已同步的研究数据失效。更换输入源也不需要替换本地查询、计算和调用层。

**硬件要求**

数据采用 Zstd 压缩存储，实际磁盘占用远小于同等 CSV 或 MySQL 方案。
