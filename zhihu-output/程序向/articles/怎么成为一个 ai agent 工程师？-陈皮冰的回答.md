### 一、我碰到的问题

今年年初开始对 AI Agent 感兴趣。起因很简单——看到群友其实是astrbot,但我完全没感觉出来，觉得牛逼非凡

然后就撞墙了。

> 其实我一直对ai蛮感兴趣但感觉和自己没关系，我之前的观念是————底层模型太困难了并且需要大量资源，个人学了没必要；而像是提示词工程这种又太没有技术含量，专门去学只感觉何意味。但现在的agent不同，确实在有一定技术含量但难度不高的舒适区域

搜了一圈教程，大概就两种：

-   **“三行代码搭 Agent”型**：pip install 一个库，跑通 demo，然后就没了。你根本不知道它为什么能跑，也不知道下次换个场景该怎么办。

> 有点像飞天闪客的agent视频，但那个视频让我受益匪浅来着，没入门的强烈建议去看看

-   **零散的博客和论文**：今天一篇讲 RAG，明天一篇讲 Multi-Agent，每篇单独看都挺有道理，但看完拼不起来——它们之间是什么关系？谁在谁之上？我应该先看哪个？

我缺的不是信息，是**一个能让我看见全景的框架**。没有人告诉我：

“Agent 这东西，从 500 行到 50 万行，中间到底经历了什么。”

后来我想明白了——框架不是看出来的，是写出来的。与其刷一百篇概念文章，不如**从小到大把真正完整的 Agent 项目复刻上一遍**。

> 之后会发复刻笔记，大概是每周一两篇的频率

这就是这篇文章的由来。

### 二、我的笨办法：从小到大抄项目

我花时间在 GitHub 上翻了一圈，挑了 6 个完整的 Agent 项目，按代码量从小到大排成一列：

```text
Stage 1  CoreCoder               ~1K行     最小可行 agent
Stage 2  mini-claude-code        ~1K行     Claude Code 骨架复刻
Stage 3  claude-code-from-scratch ~10K行   从零搭建，加子系统
Stage 4  aider                   ~100K行   生产级 AI 结对编程工具
Stage 5  OpenHands               ~200K行   全栈 agent 平台
Stage 6  AstrBot                 ~160K行   IM Bot + 插件生态
```

思路很简单：**先抄小的，理解loop；再读大的，理解架构；从原子到巨像，从最小可行到工程实现**

每个项目都是完整的、能跑的东西，不是教程片段，不是示例代码。读的是”别人真正在用的东西”。

> 我对cc提出的针对这些学习项目的筛选要求是，代码量不要太大且要优质，具有代表意义||社区生态好||用的是python可以优先，要是感觉这个项目阶梯里的项目有不好的地方评论区大胆提出来，我可以进行替换

### 三、一个一个说

### Stage 1 · CoreCoder（~950 行 Python）

**仓库**：`he-yufeng/CoreCoder`，894 个 star，还在活跃更新。

这是我见过的**最小的完整 agent**。950 行，没有抽象层，没有设计模式——就是最原始的”接收输入 → 调 LLM → 执行工具 → 把结果塞回去 → 再调 LLM”。

你一个下午就能逐行吃完。吃完之后，Agent Loop 在你脑子里就不再是概念了——它是 6 行 while 循环。

你将要学到的东西：

-   agent 最少需要几个零件才能跑
-   工具调用不是魔法，就是函数调用套了一层 JSON
-   950 行就可以做一个能读文件、写文件、搜索代码的东西

* * *

### Stage 2 · mini-claude-code（~1,100 行 Python）

**仓库**：`shareAI-lab/mini-claude-code`，352 个 star。注意这个仓库已经被作者归档了（不再更新），但代码完整可读。反而因为归档了，结构稳定，更适合学习。

和 CoreCoder 差不多大，但多了些东西：更完整的工具集、基本的权限检查、会话持久化、Skills 系统的雏形。

最好玩的是对比：**同样一千行出头，两个作者的组织方式完全不同。** CoreCoder 是什么都揉在一起但很直观，mini-claude-code 已经开始有模块意识了。

* * *

### Stage 3 · claude-code-from-scratch（~10,000 行 Python + TypeScript）

**仓库**：`Windy3f3f3f3f/claude-code-from-scratch`，1,251 个 star，活跃更新。

这是第一个”有架构”的 agent。13 章，每章往上面加一个子系统——工具系统、上下文压缩、子代理孵化、Prompt Cache、任务追踪、错误恢复。

到这一级，我开始感觉到**子系统不是在”堆功能”，而是在”解决问题”**。比如 Context Compaction 不是因为”压缩听起来很高级”，而是因为你不压缩，token 就爆了。Prompt Cache 不是因为”缓存是优化”，而是因为你不缓存，每一次调用都从头来，成本和延迟根本扛不住。

我学到的东西：

-   为什么要区分”读操作并行、写操作互斥”
-   为什么 tools 要按字母排序（和 cache 命中有关）
-   子代理为什么只能嵌套一层（递归爆炸比你想的容易触发）

* * *

### Stage 4 · aider（~100,000+ 行 Python）

**仓库**：`Aider-AI/aider`，45,172 个 star，非常活跃。

前三级的 agent “能跑”，aider “能用”——它是 4.5 万人在日常用的工具。这意味着它的错误处理是认真的、边界情况是被用户骂过的、设计决策是有原因的。

aider 最厉害的地方是 **diff/edit 工具**。它不像前三级那样”读整个文件 → 改 → 写整个文件”，而是只改需要改的那几行。听起来简单？你想想 LLM 输出天然不稳定，你怎么保证它生成的 diff 能对上原文件的格式。

到这一级，我不再逐行抄了——100K 行抄不完。我改成读核心模块、画架构图、写设计笔记。

* * *

### Stage 5 · OpenHands（~200,000+ 行 Python）

**仓库**：`OpenHands/OpenHands`，74,550 个 star。

这是目前最完整的开源 coding agent 平台。有 WebUI 管理面板、MCP/LSP 双协议集成、Docker 沙箱隔离、多代理协作、甚至集成了 SWE-bench 评估。

这一级和前面最大的区别：**前面都是”一个人用的工具”，OpenHands 是”一个平台”**。它要考虑的不只是”怎么帮一个人写代码”，而是”怎么让一群人、在不同环境、用不同配置、安全地使用 agent”。

* * *

### Stage 6 · AstrBot（~160,000 行 Python）

**仓库**：`AstrBotDevs/AstrBot`，32,873 个 star。

AstrBot 和前五级都不一样——它不是 coding agent，而是 **IM 聊天 agent 框架**。能接 QQ、微信、飞书、钉钉、Telegram 等 20 多个平台。

最吸引我的是它的**插件系统**：1000+ 插件可以一键安装，覆盖聊天、游戏、工具、娱乐。这意味着它不是一个”功能特别多的 Bot”，而是一个”能被无限扩展的平台”。

* * *

### 六级对照

| Stage | 行数 | 星星 | 怎么学 |
| ----- | ----- | ----- | ----- |
| 1 CoreCoder | ~1K | 894 | 逐行手抄，半天 |
| 2 mini-claude-code | ~1K | 352 | 逐行手抄，对比 CoreCoder |
| 3 claude-code-from-scratch | ~10K | 1,251 | 逐行手抄，三周 |
| 4 aider | ~100K | 45K | 读核心模块，画架构图 |
| 5 OpenHands | ~200K | 75K | 和 AstrBot 并排对比 |
| 6 AstrBot | ~160K | 33K | 和 OpenHands 并排对比 |

除了 mini-claude-code 已归档（代码冻结不影响学习）外，其他 5 个全部在活跃更新中。数据是cc写这篇文章时从 GitHub API 实时查的。
