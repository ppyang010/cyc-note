看评论里争论挺多，我补充一下我的看法。

不同的技术方案，都有自己擅长的领域和适用的人群，不一定非得都用某一套。

根据个人简单的应用总结，各方案的优缺点和适应人群如下：

| 方案 | 优点 | 缺点 | 适用人群 |
| ----- | ----- | ----- | ----- |
| Electron | 学习难度低、有多种 UI 框架可用，会写网页就会写；跨平台挺好 | 实现多线程、DLL 调用等方面困难，性能也较低，不是人人都能写 VSCode 这样的软件的 | Web 开发者 |
| WinForm | 学习难度低，性能较好 | 界面定制能力弱 | C# 初学者和Windows 简单应用开发者 |
| WPF | 炫，自由度大。 | 难学，一看就会上手就废。 | 学 XAML和C# 两种语言，适合有一定基础的开发者 |
| QT | QML 定制化程度高，复杂界面容易写，性能不错，写简单的容易；API 很直观 | 主要是 C++ 难度高，QT 本身控件和库都丰富；C++ 依赖管理烂； | 敢用 C++ 开发的 |
| Swing(Fx 没用过不知道，抱歉） | 性能一般、难度一般，充分发挥 Java的内存管理、跨平台特性 | 难定制风格，布局等小细节研究得费不少精力 | 深度 Java 使用者 |

* * *

以下是原答案：

个人尝试了 Vue + Electron、C# + WinForm、 C# + WPF、 CPP + QT、 Java + Swing 几种，还是最推荐 CPP + QT 的。

Electron 方案

只显示一个简单的页面很方便，但当时做的程序是一个微信机器人的项目，需要跨进程通信（使用别人的 dll），还需要后台定时处理任伤，再加上使用腾讯云的云函数。当时真是疯了，解决 https 问题、跨域问题（要欺骗腾讯云的云函数JS）、定时问题、多窗口状态维护问题，折腾了好一阵子才基本可用。但真正写逻辑的时间占比不到40%，大部分时间都是在解技术问题。

WinForm 方案 和 WPF 方案

WinForm 布局是非常简单，但是由于多年没有使用 C#，特性加的有点多，有不少关键字根本不知道啥意思，类也分好几种，对界面的控制也变的各种代理，很复杂。（原谅我水平太次，感觉 C# 有点过于强大，学不动）。

WPF 做了一个 Demo 就放弃了，回到了 WinForm。原因是这个东西简单做都容易，一旦有动态界面控制就复杂起来，并且还是需要学一门新的语言，理解它的布局原理。

Java + Swing

Swing 倒是很简单，一用就能用，Java 也没问题。但是界面的那种迟钝感，跟另外所有的方案相比都感觉太钝了。很奇怪的是我直接用代码打出来各项耗时指标，并没有多大差异，但是就是感觉很钝。

QT

这个最大的难度就是 C++了。内存无法访问的情况确实时有发生，其他的倒没啥难的。QT 提供了一个像 Java 里 Spring一样的框架，把平时用的 Map、Concurrency、Setting、……全干完了，同时提供了界面（Widgets），用的时候加上 Q\_OBJECT 啥都有了。还没试过 C# + QT，或者 Python + QT，也没试 QML，但是用了一阵子发现我出活的速度明显加快了，而且想要什么东西随手就能撸一个。这个心理成本就低了很多。

没啥推荐，都是个人经验，题主就凭自己的喜好选吧。
